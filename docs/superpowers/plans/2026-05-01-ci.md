# CI on Synthetic Demo Data (Sub-5)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans.

**Goal:** GitHub Actions runs `pipeline/refresh.sh --demo` on synthetic-only data nightly + on every PR. Fails the build if any parser regresses or the demo dashboard fails to import. Personal data never enters CI.

**Architecture:** A new `tests/demo_data/` directory holds synthetic inputs that match each parser's expected layout. `refresh.sh --demo` switches DATA_ROOT from `data/` to `tests/demo_data/` and OUTPUT to `output/web-demo/`. CI runs it, runs pytest, and verifies the generated JS imports cleanly via Node.

**Tech Stack:** GitHub Actions, Python 3.12 setup-python, pip caching, Node 20 for JS smoke-test. No new Python deps.

## Task 2 — `refresh.sh --demo` flag

**Files:**
- Modify: `pipeline/refresh.sh`

- [ ] **Step 1: Add --demo handling**

Edit `pipeline/refresh.sh`. After the `cd "$ROOT"` line, insert:

```bash
DATA_ROOT=data
PARQUET_ROOT=data/parquet
OUTPUT_JS=output/web/js
if [[ "${1:-}" == "--demo" ]]; then
    DATA_ROOT=tests/demo_data
    PARQUET_ROOT=/tmp/parquet-demo
    OUTPUT_JS=/tmp/web-demo
    rm -rf "$PARQUET_ROOT" "$OUTPUT_JS"
    mkdir -p "$PARQUET_ROOT/samples" "$PARQUET_ROOT/findings" \
             "$PARQUET_ROOT/cross_refs" "$PARQUET_ROOT/events" "$OUTPUT_JS"
fi
```

Then update every hardcoded path in the rest of the script:
- `data/parquet/.last_refresh` → `$PARQUET_ROOT/.last_refresh`
- `data/raw/healthkit/...` → `$DATA_ROOT/raw/healthkit/...`
- `data/raw/garmin/...` → `$DATA_ROOT/raw/garmin/...`
- `output/raw_findings` → `$DATA_ROOT/raw_findings` (in --demo mode this is the demo TSVs; in normal mode it's the existing pipeline outputs)
- `data/parquet/samples` → `$PARQUET_ROOT/samples`
- `data/parquet/findings` → `$PARQUET_ROOT/findings`
- `data/parquet/cross_refs/cross_refs.parquet` → `$PARQUET_ROOT/cross_refs/cross_refs.parquet`
- `output/cross_refs.yaml` → `$DATA_ROOT/cross_refs.yaml` (demo mode reads from demo dir)
- `output/web/js/data-vitals.js` → `$OUTPUT_JS/data-vitals.js`

> **Wrinkle:** in normal mode `output/raw_findings/` (existing pipeline outputs) is the source of TSVs, but in demo mode the synthetic TSVs live at `tests/demo_data/raw_findings/`. We keep them at the same relative path so a single `$DATA_ROOT/raw_findings` reference works iff we adjust normal mode's DATA_ROOT to a parent that contains `raw_findings/`.
>
> Simpler: use a separate `RAW_FINDINGS_DIR` variable: defaults to `output/raw_findings` in normal mode, `tests/demo_data/raw_findings` in demo mode.

Final variable list:

```bash
DATA_ROOT=data
RAW_FINDINGS_DIR=output/raw_findings
CROSS_REFS_YAML=output/cross_refs.yaml
PARQUET_ROOT=data/parquet
OUTPUT_JS=output/web/js
if [[ "${1:-}" == "--demo" ]]; then
    DATA_ROOT=tests/demo_data
    RAW_FINDINGS_DIR=tests/demo_data/raw_findings
    CROSS_REFS_YAML=tests/demo_data/cross_refs.yaml
    PARQUET_ROOT=/tmp/parquet-demo
    OUTPUT_JS=/tmp/web-demo
    rm -rf "$PARQUET_ROOT" "$OUTPUT_JS"
    mkdir -p "$PARQUET_ROOT/samples" "$PARQUET_ROOT/findings" \
             "$PARQUET_ROOT/cross_refs" "$PARQUET_ROOT/events" "$OUTPUT_JS"
fi
LOG="$PARQUET_ROOT/.last_refresh"
```

## Task 3 — GitHub Actions workflow

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Write the workflow**

Create `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  schedule:
    - cron: '17 7 * * *'   # 07:17 UTC daily — off the :00 mark to spread API load
  workflow_dispatch:

jobs:
  test-and-demo:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.12'
          cache: pip

      - name: Set up Node
        uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install Python deps
        run: |
          python -m pip install --upgrade pip
          pip install duckdb pyarrow pyyaml pytest

      - name: Run pytest
        run: pytest tests/ -v

      - name: Run demo refresh
        run: bash pipeline/refresh.sh --demo

      - name: Verify generated JS imports
        run: |
          node --input-type=module -e "
            import('./tests/demo_data/data-vitals-import-check.mjs').catch(() => {});
            const { VITALS } = await import(new URL('file:///tmp/web-demo/data-vitals.js'));
            const keys = Object.keys(VITALS);
            console.log('vitals keys:', keys);
            if (keys.length === 0) throw new Error('VITALS empty');
          "

      - name: Privacy guard — fail if real data leaked into git history
        run: |
          if git log --all --full-history --name-only -- 'data/' 2>/dev/null | grep -q '^data/'; then
            echo "ERROR: data/ found in git history" >&2
            exit 1
          fi
          if git ls-files | grep -E '^output/web/js/(data\.js|data-vitals\.js)$'; then
            echo "ERROR: personal data files tracked" >&2
            exit 1
          fi
```

## Acceptance criteria

- [ ] `bash pipeline/refresh.sh --demo` runs in <10s on synthetic data and produces a non-empty `/tmp/web-demo/data-vitals.js`.
- [ ] CI runs on every push to main and every PR.
- [ ] CI runs nightly via cron.
- [ ] Privacy guard step fails if `data/` ever enters git history or `data-vitals.js`/`data.js` get tracked.
- [ ] All existing pytest tests still pass on every run.

## What this plan does NOT do

- **Browser-render check.** Only verifies JS imports cleanly. Adding a Playwright job that navigates to the rendered page is a future enhancement.
- **Per-PR diff coverage / lint.** No mypy / ruff. Could be added later.
- **Deploy step.** GitHub Pages already auto-deploys from `docs/` on every push to main; no separate deploy needed.
