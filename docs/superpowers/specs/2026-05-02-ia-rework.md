## Programming, without a logger

**Adherence-based.** For each prescribed Day, we compute:

```
prescribed_day = Day {1..7} per day-of-week
matched_garmin_event = WHERE events.ts_start IN (today's window)
                       AND events.type='workout'
                       AND match_sport_to_program(...)
```

Where `match_sport_to_program` is:
- Day 1 / 3 (Push) → strength_training, indoor_workout (no clear push/pull tag in Garmin sport types, treat any strength session as match)
- Day 2 / 4 (Pull + Lower) → same
- Day 5 (Yoga) → yoga
- Day 6 (Sport) → tennis, cycling, swimming, hiking, badminton, etc.
- Day 7 (Rest) → no expectation

We surface a small chip:
- ✓ `done via Garmin` (matched Garmin event today)
- ⏱ `pending` (no event yet, day not over)
- ✗ `missed` (day over, no match — for prior days)

**No exercise tracking.** The static prescription stays static. If you want progressive overload tracking, that's a real workout-logger app (Hevy/Strong) — out of scope.

Future enhancement when we build it: ingest Hevy / Strong CSV exports, same way we ingest Garmin/HealthKit.

## Visual cleanup pass

**Card variants (max 3):**
- `card-info` — neutral, no left border, used for trends/data
- `card-action` — left border `--accent` (cyan), used for things needing user attention
- `card-warn` — left border `--warn` (red), used for med alerts and hard-off targets

**Density rules:**
- Section title: italic serif, 1.4-2rem, mono eyebrow above
- Card title: italic serif, 1rem-1.15rem
- Card body: italic serif 0.85rem (was inconsistent — sometimes mono, sometimes serif)
- Pills/labels: mono caps, 0.55rem, letter-spacing 0.18-0.22em (already consistent — keep)
- Borders: 1px `--border` for grids, 2px `--accent`/`--warn` for action/warn lefts
- **Drop:** the inconsistent "data-state" colored vertical bars on Action Loop cards — replace with subtle background tint instead

**Color tokens audit:**
- `--accent` (cyan) = action / live data
- `--rune` (green) = on-target / success / positive trend
- `--warn` (red) = off-target / alerts / negative trend
- `--fg-dim` (50% white) = secondary text
- `--fg-mute` (30% white) = tertiary
- Stop using saturated cyan for both "live data" and "section heading" — section eyebrows go to `--fg-dim`.
